# 与 cross-agent-memory 的联动约定

`cross-agent-dev-workflow` 在记忆中保存可续跑的阶段状态；`cross-agent-memory` 用精简路由索引和按需主题阅读降低接手成本。

## 阶段 0 接手

1. 读根层 `0_索引.md`，了解分层职责、全局约束和明确例外。
2. 读根层当前 `5_代办.md`，定位活跃任务或需核实的旧状态。
3. 按任务路径读取目标层 `0_索引.md`、`5_代办.md` 和相关主题；不要默认通读兄弟层或全部主题文件。
4. 按 cross-agent-scratchpad 协议核对本机脚本库配置；没有可信遗留物审计记录时才进行首次全面脚本审计。
5. 从相关层的 `5_代办.md` 的 `🚦` 段恢复阶段、证据、阻塞与下一步。

工具入口：

```powershell
python "<cross-agent-memory技能目录>\工具\记忆管家.py" 接手 <工作区> --scope <任务路径>
```

该命令为快速路径，只校验根至目标路径的记忆层与状态并检查本机脚本库配置。未提供 `--scope` 时只检查根层。只有首次初始化、工作区结构变化、记忆冲突/缺失或用户明确要求全面审计时，才运行 `接手 <工作区> --full-audit` 或 `检查 <工作区>`。

## 交付状态维护

| 信息 | 记忆位置 | 更新时机 |
|---|---|---|
| 阶段、档位、当前目标、已完成、下一步、阻塞与证据 | 任务对应层 `5_代办.md` 的 `🚦` 状态段 | 阶段转移、阻塞或关键进度变化时 |
| 验收清单 | 项目验收清单，或 `5_代办.md` 的短摘要与链接 | 研发启动和验收过程 |
| 方案取舍 | 有内容时的 `决策.md` | 方案拍板后 |
| 可复用问题/修复 | 按需创建的 `2_踩坑日志.md` | 确认根因和解决方式后 |
| 用户明确偏好 | 按需创建的 `3_个性化需求.md` | 有稳定、可复用偏好时 |
| 结构变化 | 按需创建的 `1_项目架构.md` | 结构确有变化时 |

写入前重读目标文件并合并，必要时用 `记忆索引.json` 检测并发修改；回读写入结果。只记录能帮助未来续跑的信息，不把逐轮过程复制进长期记忆。状态路径保持相对或用 `<工作区>` 占位符。

若 memory 未安装，临时使用工作区 `交付状态.md` 保留当前阶段；memory 恢复后再合并迁入对应范围层的 `5_代办.md`。
