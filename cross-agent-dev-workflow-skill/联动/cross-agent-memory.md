# 与 cross-agent-memory-skill 的联动约定

本技能与 `cross-agent-memory`（就地记忆）是**承载关系**：本技能定流程（阶段/验收门/停止闸），memory 存状态与知识——**本技能的阶段状态机就放在 memory 的 `5_代办.md` 里**，没有 memory，流程就成了无状态的裸提示词。

## 一、接手任务入口（三位一体合并流程）

```
接手任务
 ├─ 1. 一键入口：python 记忆管家.py 接手 <工作区>
 │      （= 记忆扫描 + 分层完整性 + 并发校验 + 临时脚本库配置联动检查）
 ├─ 2. 读根层 0_索引（分层方案）→ 深读记忆文件；无记忆 → 深读整个项目
 ├─ 3. 读 5_代办.md 的「🚦 交付流程状态」段 → 有状态从断点续跑，无状态定档起步
 └─ 4. 执行任务：按本技能阶段协议走，全程按 memory「写前三步」更新记忆
```

## 二、本技能会往 memory 的哪些文件写什么

| 信息 | 写入位置（memory） | 写入时机 |
|---|---|---|
| **「🚦 交付流程状态」段**（档位/当前阶段/进度/证据/转移日志） | `5_代办.md` 固定段 | 每次阶段转移、每次收尾 |
| 用户验收期望翻译成的可核查条目 | `5_代办.md`（或项目内验收清单文件+直链） | 阶段 1 开始时 |
| 选型决策（候选/推荐/弃用理由）、拍板结论 | `决策.md`（可选扩展，追加式） | 阶段 1 |
| 研发/测纠中踩的坑（问题/根因/解决/影响） | `2_踩坑日志.md` | 实时 |
| 用户在交付过程中说的偏好 | `3_个性化需求.md` | 实时 |
| 发布整理造成的结构/口径变化 | `1_项目架构.md` | 阶段 3 |
| 更新日志（本轮做了什么） | `0_索引.md` | 每次收尾 |
| 待用户拍板事项（含 scratchpad quarantine 项） | `6_需要我配合.txt` | 随时 |
| 跨周期交接 | `交接简报.md`（可选） | 发布后或长任务中断时 |

## 三、memory 对本技能的约束

- 本技能一切记忆写入遵守 memory 的「**写前三步：先读→合并→写回**」与追加式条目纪律（带日期+署名），配合 `记忆索引.json` 指纹校验防并发覆盖。
- 状态段格式固定（SKILL.md §五），转移日志**只追加不改写**——任何 Agent 都能回放流程历史。
- 记忆里不写机器专属绝对路径（memory 的路径可移植性规则同样约束本技能的状态段）。

## 四、本技能未安装 memory 时的降级

按 SKILL.md §六 三条铁律：工作区维护 `交付状态.md`（同格式）承载状态机；临时脚本不落工作区；删除先问用户。装回 memory 后把 `交付状态.md` 内容合并进 `5_代办.md` 状态段（先读→合并→写回）。
