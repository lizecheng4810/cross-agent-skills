# 与 cross-agent-scratchpad-skill 的联动约定

本技能与 `cross-agent-scratchpad-skill`（临时脚本治理）是**委托关系**：本技能的三个阶段都会产生临时脚本和遗留物，**怎么建、怎么复用、怎么删，全部委托 scratchpad 的协议**——本技能只负责在正确的节点调用它。

## 一、各阶段的委托点

| 阶段 | 本技能的动作 | 委托 scratchpad 的动作 |
|---|---|---|
| 阶段 0 接手 | 共用一键入口 | 本机配置检查（库路径）+ 遗留物审计（增量） |
| 阶段 1 研发 | 研究脚本、原型脚本、数据处理脚本的需求 | 节点 2：先查库复用 → 没有才建 → 建在外部库 + 登记 |
| 阶段 2 测纠 | 测试脚本、复现脚本、比对脚本的需求 | 同上；测试输出/证据留存（外部库 `reports/` 或项目文档） |
| 阶段 3 发布 | 判定哪些文件是旧迭代遗留 | **分级处置**：A 自己 / B 复用迁入 `reusable/` / C 无价值记录后清理 / D 来源不明→隔离+等用户确认 |
| 收尾 | 报告与记忆更新 | 节点 3：本次脚本收编/清理/隔离 + 索引更新 |

## 二、删除红线（本技能的硬约束）

- 本技能的「整理发布」涉及删除/移动/重命名时，**一律走 scratchpad 的分级处置协议**，绝不越级：
  - 真实工程文件、构建配置、依赖清单、文档、数据文件、git 跟踪文件、任何拿不准的文件——**默认绝不自动删除**；
  - 来源不明的 → 只隔离 + 报告 + 等用户确认（列入记忆 `6_需要我配合.txt`）；
  - 优先移系统回收站而非永久删除；git 已跟踪的靠历史兜底（先提交再删）。
- 用户授权「全部权限」不解除本红线——授权是效率授权，不是破坏授权。

## 三、scratchpad 的结论写回本流程

| 信息 | 去处 |
|---|---|
| 审计结论「该工作区已审计 + 日期」 | 记忆 `1_项目架构.md` / `5_代办.md`（下轮跳过全量审计） |
| quarantine 待拍板项 | 记忆 `6_需要我配合.txt`（发布报告中显式列出） |
| 迁移/清理的依据与结果 | `决策.md` + 外部库 `reports/`（发布清单「无未处置遗留物」的证据来源） |
| 用户对脚本治理的偏好 | 记忆 `3_个性化需求.md` |

## 四、本技能未安装 scratchpad 时的降级

按 SKILL.md §六 三条铁律：临时脚本绝不落项目工作区（用完即删或建到外部目录）；删除操作一律先问用户。装回 scratchpad 后补做一次遗留物审计。
