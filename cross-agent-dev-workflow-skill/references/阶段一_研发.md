# 阶段 1 · 研发迭代（细则）

> 前置：阶段 0 已完成（读过记忆/分层方案、定了档位）。本阶段目标：**从「要做什么」走到「做出来了且方案有据」**。

## 1.1 深度研究理解

1. **读透上下文**：记忆（`0_索引`→`5_代办`→`1_项目架构`→其余）+ 相关源码/文档；没有记忆则深读整个项目。
2. **翻译验收期望**：把用户的话（如「可上线发布的完整成品」）翻译成本项目可核查的验收清单（条目化、可打勾），写入项目（如 `验收清单.md` 或记忆 `5_代办`），供阶段 2/3 直接复用。
3. **批判性前置**：检查用户需求中的错误前提、逻辑跳跃、信息缺失；发现即指出，不带错硬做。区分事实/预测/观点；无法核实的标注「未验证」。

## 1.2 资产检索（深度档必做；标准档按需）

1. **GitHub 检索策略**：技术栈 + 功能关键词 + 备选词（中文/英文各一轮）；优先看 star/维护活跃/license 兼容（MIT/Apache 优先，GPL 需标注传染性风险）。
2. **联网调研**：论文、官方文档、他人成果、最佳实践、已知坑（搜「<方案> pitfall/坑」）。
3. **复用判定**：`改造成本 + 学习成本 + 维护风险` vs `自造成本`；复用不硬凑——改造成本明显更高时如实记录并放弃。
4. **选型留痕**：候选对比 + 推荐 + 弃用理由写入记忆 `决策.md`（追加式，带日期+署名）。
5. **检索止损**：连续 2~3 轮检索无增量信息即收，转方案设计；记录「检索了多少轮、覆盖了什么、还差什么」。

## 1.3 方案设计

1. 输出**至少 1 个候选方案**（深度档 ≥2 个做对比）：做法、影响面、依赖、风险、隐性成本（时间/token/维护负担）。
2. **拍板线**（SKILL.md 总则 4）：架构选型、对外接口、不可逆操作、超出原需求范围的想法 → 先给方案等用户决断；拍板结论记入 `决策.md`。
3. 方案要落到**可执行的任务分解**（谁先谁后、每步怎么验证），分解结果写入 `5_代办`。

## 1.4 实现与多轮迭代

每轮迭代的固定动作：

```
小步实现 → 自测（能跑的最小验证） → 记录 → （未达验收）→ 下一轮
```

- **小步**：一轮只解决一个主题；大改拆轮次，避免一次动太多无法定位回归。
- **记录**（实时，不等收尾）：
  - 进度/下一步 → `5_代办.md`（含「🚦 交付流程状态」段）
  - 踩坑（问题/原因/解决/影响）→ `2_踩坑日志.md`
  - 用户偏好（命名/风格/口径）→ `3_个性化需求.md`
  - 被确认的决策 → `决策.md`
- **临时脚本**：一律外部库（scratchpad 节点2：先查库复用，没有才建，建在库内不落工作区）。
- **授权边界**：用户授权的安装/下载按授权执行；但授权不等于义务——每一步先判断是否真需要。
- **安装位置协议**：需要下载安装软件/技能/插件/扩展时，**不散装乱放**——①先查工作区记忆或本机配置里的「软件安装位」；②有指定位置（如 `D:\Agent下载`）→ 用它，文件夹不存在则**先创建**再安装；③没指定 → **先询问用户**要装在哪，得到答复后按 ② 执行并把该位置记入记忆（供本设备后续复用）。

## 1.5 阶段验收门（全过才转移）

| # | 检查项 | 证据形式 |
|---|---|---|
| 1 | 需求功能达成（对照 1.1 翻译出的验收清单） | 功能逐项演示/测试输出 |
| 2 | 方案落地与选型留痕一致 | `决策.md` 条目 |
| 3 | 记录完整（进度/坑/偏好实时入记忆） | 记忆文件直链 |
| 4 | 无未披露假设（外部依赖、环境要求、未做的部分） | 报告中显式列出 |
| 5 | 拍板线事项均已获用户确认 | 对话/`决策.md` |

→ 全过：在 `5_代办` 状态段追加 `[日期] [署名] 阶段转移：阶段1→阶段2`，进入阶段 2。

## 常见跑偏与对策

| 跑偏 | 对策 |
|---|---|
| 无限检索不下场 | 1.2 第 5 条止损规则 |
| 自造已有轮子 | 资产检索强制在前 |
| 闷头实现不打扰用户 | 撞拍板线必须停（总则 4） |
| 一轮改太多 | 小步原则 + 每轮自测 |
| 做着做着加戏 | 对照验收清单，清单外=阶段 3 之后再议 |
