# 阶段 2 · 测试纠错（细则）

> 前置：阶段 1 验收门已过。本阶段目标：**从「做出来了」走到「有证据地没有已知问题」**。
> 核心纪律：本阶段是**实际运行 + 逐文件审查**，不是纸面走查；自己写的自己测天然偏松，一切以证据为准。

## 2.1 实际运行测试

1. **真跑**：用真实命令、真实环境、有代表性的真实数据/输入样本，把项目跑起来。
2. **覆盖路径**：主流程（happy path）+ 已知边界（空输入/超长/并发/路径含空格与中文等）+ 阶段 1 验收清单逐项。
3. **跑不了怎么办**：环境缺失（如无数据库/无某 OS）→ 写明原因 + 用替代验证（单元级/模拟/逻辑推演）+ 在已知问题清单标注「未实测项」。**禁止静默跳过**。
4. 测试用的临时脚本 = 临时脚本，走 scratchpad（外部库、先复用）；测试输出/日志留存为证据（可放外部库 `reports/` 或项目文档，不污染工作区）。

## 2.2 逐文件深度审查

1. **全量清单化**：列出项目全部文件（含配置/文档/脚本），逐个过，标记 `OK` 或 `问题 + 根因 + 建议修复`。
2. 审查维度按文件类型：代码（逻辑/边界/错误处理/编码/路径假设）、配置（与文档一致性）、文档（与实际行为一致性、口径统一）、数据文件（是否该进版本库）。
3. **不抽样**：没看的文件必须显式声明「未审查 + 原因」，不得含糊带过。
4. 机器可查的先机器查：lint/语法检查/结构校验工具（如 `发布管家.py 校验技能`之于技能包）能覆盖的先跑工具，人工聚焦工具覆盖不到的。

## 2.3 纠错循环

每轮纠错循环都要在项目验证记录中留证。只有能帮助未来任务避免重踩的已确认根因与修复，才归纳到 `2_踩坑日志.md`；不把每轮完整记录复制进长期记忆：

```
[轮次N] 问题：<现象> → 根因：<为什么> → 修复：<改了什么> → 验证：<怎么证明修好了>
```

- **回归检查**：每轮修复后重跑受影响的验证点（修 A 坏 B 是本阶段最大风险）。
- **根因优先**：修根因不修表象；连续两轮修同一位置说明根因没找对，停下来重新分析。
- **设计级问题**（实现再对也不满足需求/架构有硬伤）→ 回退阶段 1，在 `5_代办` 状态段如实记录 `阶段2→阶段1` 与原因。

## 2.4 证据制验收门（全过才转移）

| # | 检查项 | 证据形式 |
|---|---|---|
| 1 | 实际运行通过（主流程 + 边界 + 验收清单项） | 命令与输出摘录 |
| 2 | 逐文件审查完成（全量清单，无未声明遗漏） | 审查清单（文件×结论） |
| 3 | **已知问题清单为空**（或全部为用户已知悉的接受项，逐条标注） | 已知问题清单（可为空表） |
| 4 | 纠错记录完整（问题/根因/修复/验证 四要素齐全） | 循环记录 + `2_踩坑日志.md` |
| 5 | 无回归（最近一轮修复后全量验证点重跑通过） | 重跑输出 |
| 6 | 深度档：未参与编写的子 Agent 复审通过（无此能力时显式声明降级） | 复审结论 |

→ 全过：更新 `5_代办` 当前阶段、最近转移、进度、证据链接和下一步，进入阶段 3。完整验证记录保留在项目验收记录，不在记忆状态段重复堆叠。

## 关于「完全没有问题」的口径（重要）

工程上不存在绝对无问题；本协议把它操作化为：

> **已知问题清单为空 + 验收清单全过 + 未实测项已显式披露并经用户接受。**

向用户报告时用这个口径，不用「绝对没问题」这种无法核查的承诺。

## 常见跑偏与对策

| 跑偏 | 对策 |
|---|---|
| 只看不跑 | 2.1 真跑纪律 |
| 抽样审查冒充全量 | 2.2 清单化 + 未看必声明 |
| 修表象不修根因 | 2.3 根因优先 + 连续两轮同位置即停 |
| 修 A 坏 B | 每轮回归检查 |
| 自评偏松 | 证据制 + 深度档子 Agent 复审 |
