# 记忆更新、时效与并发安全

## 何时写记忆

只记录未来可能影响工作质量的持久信息：已验证的架构/行为、根因与修复、用户明确偏好、重要决定、跨会话进度或可复用步骤。临时推理、普通问答、一次性状态和可直接从项目读取的内容通常不写。

每次任务结束时先判断是否有值得保留的变化；没有就不改文件，也不为“每次对话都更新”制造空操作。交付任务有状态变化时，更新根层或相关范围的 `5_代办.md`。

## 写入前后

对目标文件执行“读—合并—写回”：

1. 只重读准备修改的文件和其必要上下文，保留未相关内容；
2. 有 `记忆索引.json` 时校验目标记录指纹；文件在读取后变化，重新读取并合并；
3. 更新内容并刷新对应指纹/元数据；
4. 回读已写文件，确认路径、链接、编码和要点。

多个 Agent 并发时优先按层/主题分配写入责任，避免同时覆写同一文件。校验或合并失败时不要以旧快照强制覆盖；将冲突留在工作区并报告。

## 时效与证据

区分观察事实、用户判断、推测和待确认项；能标注日期、代码路径、版本或验证方式时就标注。运行态、版本、依赖、配置和当前代码行为易变，接手时应实查来源。记忆不是事实数据库，也不取代当前文件、测试、日志或用户本轮指令。

当决定被替代或信息过期时，直接修订权威主题记录并留下必要的决策变化；不要持续追加相同事实使索引变成无边界日志。

## 控制记忆体积

- `0_索引.md` 是路由表，优先只列范围、主题、触发词和直链；避免复制主题正文。结构/路由更新日志最多保留最近 3 条，其余内容合并为当前方案。
- `5_代办.md` 是单个活跃任务的恢复卡。交付完成后清除已完成事项，只保留下一周期待办或明确的“无”；可追溯验收细节留在项目验收/发布记录，并在需要时链接。
- 主题记录保存仍有效的摘要与依据；过时事实应更新或标为已替代，不按轮次盲目追加。大段证据留在代码、日志、报告等权威来源，记忆只留位置和结论。
- 当单个主题已难以快速浏览时，按明确主题拆分成更小文件并更新索引；不按目录机械拆分，也不为了达到固定文件数制造空文件。

## 便携路径

记忆文件中的项目路径写相对路径或 `<工作区>` 占位符。个人机器配置只有在必须保留时，标注其为本地、可变配置，并说明如何重新发现；不要把机器专属绝对路径描述为项目事实。
