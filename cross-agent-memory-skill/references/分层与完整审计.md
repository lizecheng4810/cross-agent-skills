# 分层与完整审计

## 何时创建记忆层

记忆层表达可复用上下文的边界，不是目录树的镜像。仅当一个项目/子项目具有独立目标、架构、交付周期或持续 Agent 交接需求，并且上下文不能用少数根层链接表达时，才考虑新增层。目录深度本身不是新增理由。

建层前先检查最近的根索引、已有邻近层及项目结构。把不建层的关键范围写入根索引，防止后续审计把例外误判成遗漏。首次初始化时可以深度检查全项目以确定层数；层数由结构和认知边界决定，可为 1 至 N。

默认新层只创建：

- `0_索引.md`：范围、上级链接、路由和按需主题文件；
- `5_代办.md`：当前状态与下一步。

其他主题文件在有稳定、可复用内容时再创建。用户或既有项目明确要求旧式齐全目录时，可运行 `建层 ... --完整模板`；工具仍应能读取旧式六文件记忆。

## 完整性检查触发条件

日常接手不必扫描与任务无关的目录。仅在首次初始化、工作区结构显著变化、用户要求，或当前任务揭示已有分层存在盲区时，执行全工作区完整性检查。新增目录先核实它是否真的代表独立上下文，再决定建层；候选名单不是自动建层清单。

完整审计默认不限目录深度，忽略符号链接/目录联接以避免循环及意外离开工作区。可用最大深度参数限制范围。被忽略目录、权限错误或扫描失败要在结果里报告，不能据此声称审计覆盖完整。

示例：

以下命令从 `cross-agent-memory-skill` 技能目录运行。

```powershell
python 工具\记忆管家.py 检查 <工作区>
python 工具\记忆管家.py 检查 <工作区> --scope <工作区内的目录> --max-depth 4
```

候选检查只辅助发现：源码树中可能存在独立项目的目录。必须由 Agent 结合根分层方案和可复用上下文决定；测试数据、依赖缓存、构建产物、模板/技能发布包等常见情况下不建层。

## 根索引要求

根层索引维护分层方案、各层职责、定层依据和关键例外。新增/合并/拆分层时同步更新它，并更新相邻层的上下级链接。不要逐个复制同一段全局知识；用相对链接指回权威位置。

分组文件夹若不承载独立记忆层，不参与层号。层号按已确认的记忆层级序数，而非目录嵌套深度。新增结构先更新方案，再执行补齐，避免自动检查篡改原有认知边界。
