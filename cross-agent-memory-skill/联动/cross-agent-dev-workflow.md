# 与 cross-agent-dev-workflow-skill 的联动约定

本技能与 `cross-agent-dev-workflow-skill`（项目交付总流程）是**三位一体**关系：**dev-workflow 掌舵、本技能记账、scratchpad 打扫**。dev-workflow 把「深度研究 → 研发迭代 → 测试纠错 → 整理发布」固化为阶段协议，而它的**状态与知识全部沉淀在本技能的记忆文件夹里**。

## 一、dev-workflow 存放在本技能里的东西

| 信息 | 位置（本技能） | 说明 |
|---|---|---|
| **「🚦 交付流程状态」段**（档位/当前阶段/进度/证据/阶段转移日志） | `5_代办.md` 固定段 | 状态机载体：接手 Agent 读它即知断点，跨会话跨 Agent 续跑 |
| 用户验收期望翻译成的可核查条目 | `5_代办.md`（或项目内验收清单 + 直链） | 阶段 1 起步时建立，阶段 2/3 复用 |
| 选型决策（候选/推荐/弃用理由）、拍板结论 | `决策.md`（可选扩展，追加式） | 阶段 1 |
| 研发/测纠中踩的坑 | `2_踩坑日志.md` | 实时追加 |
| 交付过程中用户说的偏好 | `3_个性化需求.md` | 实时 |
| 发布整理造成的结构/口径变化 | `1_项目架构.md` | 阶段 3 |
| 待用户拍板事项（含 scratchpad quarantine 项） | `6_需要我配合.txt` | 随时 |
| 收尾/交接摘要 | `0_索引.md` 更新日志、`交接简报.md`（可选） | 每轮收尾 |

## 二、本技能对 dev-workflow 的约束

- 一切写入遵守「**写前三步：先读→合并→写回**」，追加带日期+署名的条目，不改写他人的历史行（含状态转移日志）。
- 状态段里**不写机器专属绝对路径**（本技能的路径可移植性规则同样适用），证据用相对路径/直链。
- dev-workflow 未安装本技能时以 `交付状态.md` 降级承载状态机；装回后先读→合并→写回 `5_代办.md` 状态段。

## 三、共用接手入口（三技能一次深读）

```
python 记忆管家.py 接手 <工作区>
（= 记忆扫描 + 分层完整性检查 + 并发校验 + 临时脚本库配置联动检查）
→ 读 5_代办「🚦 交付流程状态」定续跑点 → 按 dev-workflow 阶段协议执行
```
