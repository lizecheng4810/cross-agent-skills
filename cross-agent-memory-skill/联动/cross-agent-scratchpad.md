# 与 cross-agent-scratchpad-skill 的联动约定

本技能与 `cross-agent-scratchpad-skill`（临时脚本治理）是共生关系：本技能负责「理解和记录项目知识」，scratchpad 负责「临时脚本建在哪、能不能复用、何时删」。**两者共用同一个接手任务入口，一次深度阅读同时服务两者。**

## 一、接手任务入口（合并流程）

```
接手任务
 ├─ 1. 读项目记忆 记忆第X层/（本技能：有记忆读记忆，无记忆深读项目）
 │      先读 0_索引 → 5_代办 → 6_需要我配合 → 其余各件；逐层向上读父层
 ├─ 2. 层级完整性检查（本技能）：新增子工程/模块 → 主动补齐 记忆第三层
 ├─ 3. 读本机配置 ~/.agent-tsg/config.json（scratchpad）→ 未配置则问用户要临时脚本库路径
 ├─ 4. 记忆中有「已审计」标记？ ──有──→ 跳过全量审计，只看增量
 │        └─没有→ 执行遗留物审计（scratchpad 节点1），结果写回记忆
 ├─ 5. 执行任务（临时脚本走 scratchpad 节点2；踩坑/偏好随时按本技能更新记忆）
 └─ 6. 收尾：处置本次脚本（scratchpad 节点3）+ 更新索引 + 按本技能「读后改不覆盖」更新记忆
```

## 二、scratchpad 会往本技能的哪些文件写什么

| 信息 | 写入位置（本技能） | 说明 |
|---|---|---|
| 用户对临时脚本治理的偏好（保留期、命名、敢不敢删） | `3_个性化需求.md` | 用户亲口说的偏好是最高价值 |
| 「该工作区已完成遗留物审计 + 日期 + 结论」 | `1_项目架构.md` 末尾或 `5_代办.md` | 避免下一个 Agent 重复全量扫描 |
| 脚本相关的坑（路径失效、依赖冲突、必须在工作区跑等） | `2_踩坑日志.md` | 问题/原因/解决/影响 |
| 待迁移/待清理/待审计 | `5_代办.md` | 跨 Agent 接续任务 |
| quarantine 待用户拍板项 | `6_需要我配合.txt` | 按重要性排序 |
| 每次保留/迁移/删除的依据和结果 | `决策.md`（可选扩展）+ scratchpad 库 `reports/` | 审计留痕 |

> 注意：**本机临时脚本库路径**（`~/.agent-tsg/config.json`）是设备级事实，**不放记忆**——跨设备不通用。

## 三、并发安全（两技能共用）

- 更新记忆一律遵守本技能的「**写前三步**」：先读 → 合并自己的更新 → 写回；有指纹档案（`记忆索引.json`）时先用 `校验` 检测外部改动。
- 记忆更新以**追加带日期+署名的条目**为主，少做整段重写；定期整理时才压缩。
- scratchpad 的 `manifests/index.json` 现已工具化兜底：保存前重读磁盘做指纹比对、原子写入（借鉴本技能的指纹保护思想）——被并发改过会拒写并提示重读合并。
- **一键接手入口**：`python 记忆管家.py 接手 <工作区>` 一条命令跑完「扫描记忆层 + 层级完整性检查 + 各层并发校验 + 临时脚本库配置联动检查」，两技能共用。
- **署名统一**：本机 `~/.agent-tsg/config.json` 的 `agent_name`（由 scratchpad `配置 --name` 设置）被两个工具共用，`索引/校验/登记/迁移` 的 `--by` 省略时自动取它，跨技能留痕一致。

## 四、层级对应

- 治理偏好属于**第1层**（工作区通用）；某项目的审计结论、quarantine 项属于**第3层**（该项目记忆）。
- 设备级配置（库路径）不属于任何记忆层。
