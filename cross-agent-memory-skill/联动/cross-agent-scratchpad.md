# cross-agent-memory × cross-agent-scratchpad

`cross-agent-memory` 保存工作区可复用上下文；`cross-agent-scratchpad` 管理外部临时脚本库与脚本遗留物。两者共用接手入口，但记忆读取保持按任务范围渐进。

## 接手顺序

```text
接手任务
 ├─ 读根记忆层 0_索引 + 当前 5_代办
 ├─ 按任务路径读范围层 0_索引 + 5_代办 + 相关主题
 ├─ 读本机配置 ~/.agent-tsg/config.json（设备级，不写入项目记忆）
 ├─ 有可信「已审计」标记 → 仅检查增量；无标记 → 做首次脚本遗留物审计
 └─ 任务结束时按元数据处置本次脚本，只记录长期有用的偏好/坑/结论
```

快速入口：

```powershell
python "<cross-agent-memory技能目录>\工具\记忆管家.py" 接手 <工作区> --scope <任务路径>
```

未给范围时只校验根层；`--full-audit` 用于明确的全工作区记忆审计。memory 完整性候选只是线索，不能替代根分层方案，也不授权自动建层。

## 记忆写入位置

| 内容 | 写入位置 |
|---|---|
| 用户明确表达的脚本治理偏好 | 有内容时的 `3_个性化需求.md` |
| 稳定的工作区审计结论/范围 | 相关层的 `5_代办.md` 或 `1_项目架构.md` |
| 可复用脚本故障与根因 | 有内容时的 `2_踩坑日志.md` |
| 尚待处理的迁移、清理或隔离事项 | 相关层 `5_代办.md`；需用户确认的事项另进 `6_需要我配合.txt` |
| 本机临时脚本库路径 | 本机 `~/.agent-tsg/config.json`，不进工作区记忆 |
| 脚本元数据、哈希、审计报告 | 外部脚本库 `manifests/` 与 `reports/` |

记忆在有稳定事实或任务状态变化时更新，不为每轮对话追加无意义记录。写入时按目标文件“读 → 合并 → 写回”，检测并发变化后重新读取合并。真实项目文件仍遵循 scratchpad 的分类与删除红线。

## 通用知识与层级

治理偏好只有用户明确说是跨项目通用时才放进 `记忆_通用/`；项目专属审计结果写入对应范围层。分层方案、例外目录和层号由根层 `0_索引.md` 决定。设备级库路径不属于任何记忆层。
