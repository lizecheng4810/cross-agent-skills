# 跨 Agent / 跨 Harness 就地记忆

## 目的与使用范围

记忆留在真实工作区中，并能随工作区跨 Agent、Harness 和设备交接。目标是缩短恢复上下文的时间，同时保留足够的证据、状态和决策线索。

只要在真实工作区中执行任务，就使用本协议。**技能常开不等于每次读完所有记忆**：常规接手走快速路径；仅在明确定义的触发条件下扩展。记忆用于路由和恢复，当前代码、配置、日志和用户本轮指令才是易变事实的核对来源。

## 常规快速路径

1. 读工作区根记忆层 `0_索引.md`，确认分层方案、约束和明确例外。
2. 读根层 `5_代办.md` 的当前交接；若记录已过期，标记待核实，不照搬为事实。
3. 从用户目标/路径确定任务范围，只读该范围最深相关层的 `0_索引.md` 与 `5_代办.md`。
4. 按索引中的链接和触发条件，打开与本任务直接相关的主题文件；不默认读取兄弟模块或每层全部文件。
5. 核对会影响当前动作的代码、配置、状态或版本；若记忆与新证据冲突，以当前证据和用户本轮指令为准，并在适当范围修订记忆。

任务路径不明确时，先用索引和有限关键词检索定位。找不到时扩大范围，不能把“没命中”当作“没有记忆”。

## 何时扩大读取或全量审计

满足以下任一情况，逐步扩大到相关父层/主题；仅在仍有缺口或需要全面盘点时全量审计：

- 工作区首次初始化，尚无可信分层方案或记忆；
- 目标层索引/交接缺失、陈旧、损坏，或与项目现状冲突；
- 任务跨多个模块，或某个决策会影响其他范围；
- 工作区结构显著变化，可能需要重新判断分层；
- 并发写入的指纹校验失败，或发现另一 Agent 更新了目标记忆；
- 用户明确要求完整接手、记忆审计或历史追溯。

扩大读取采取最小充分范围：目标层 → 直接父层 → 相关兄弟层；不要无理由从局部问题升级为全库阅读。首次初始化时才深度研究项目结构并为其定层。

## 分层和文件规则

- 层数不是固定值，按独立目标、架构、生命周期和交接需求确定 1~N 层；层号表示记忆层级序数，不等于目录嵌套深度。
- 根层 `0_索引.md` 是唯一权威分层方案，需记录各层职责、依据与不建层的关键例外。
- 记忆层表达可复用上下文边界，不是目录树镜像。目录新增或被工具列为候选时，先判断是否值得独立记忆；禁止按候选列表机械建层。
- 新层默认只含 `0_索引.md` 和 `5_代办.md`。主题文件在确有稳定内容时创建；用户或既有工作区要求齐全模板时可选择旧式完整模板。
- 既有六文件布局继续兼容：`0_索引.md`、`1_项目架构.md`、`2_踩坑日志.md`、`3_个性化需求.md`、`4_提示词配方.md`、`5_代办.md`（以及可选的 `6_需要我配合.txt`）。空文件不是完整性的目标。
- 明确的例外目录应写入根索引。技能包、模板和发布制品通常不嵌入自身项目记忆，除非根方案有具体理由。

模板和边界细则见 [分层与完整审计](references/分层与完整审计.md)。

## 任务结束时更新

仅在本轮产生了可复用的新事实、已验证的坑/修复、用户明确偏好、已作出的重要决定，或持续任务的交接状态变化时写入。普通问答、临时推理、一次性输出或可直接从项目读取的信息，不需要记忆更新；没有持久变化就跳过写入。

写入时：

1. 定位单一权威层和主题，优先修订已有内容，不复制到多个层；
2. 读目标文件与必要上下文，按“读 → 合并 → 写回”保留无关内容；
3. 若存在 `记忆索引.json`，按其格式校验目标记录的指纹；发现目标在读取后变化，重读合并，不覆盖新内容；
4. 回读修改后的文件，核对准确性、链接、路径与编码；
5. 有持续任务进度时，令 `5_代办.md` 指向最后完成动作、下一步、阻塞和状态依据，不复制长篇过程日志。

并发、时效和证据要求见 [记忆更新与并发安全](references/记忆更新与并发安全.md)。

## 工具使用

提供的 `工具/记忆管家.py` 是可选助手，不替 Agent 判断分层或记忆是否仍有效。使用前看 [工具说明](工具/README.md) 及 `--help`。常规快速接手可传入目标范围；完整审计必须显式请求。工具检查所报告的“候选层”不是建层命令。

记忆文件存放于目标工作区根目录下的 `记忆第一层/`，下级记忆目录按已确认的层级序数命名。文件路径一律用工作区内相对路径或 `<工作区>` 占位符。

## 中央通用记忆

只有用户明确说明属于跨项目通用知识时，才写到工作区根目录的 `记忆_通用/`；各层通过 `0_索引.md` 的 `## 🔗 通用知识` 链接引用，不复制全文。项目专属结论仍留在所属范围。细则见 [通用知识与可移植性](references/通用知识与可移植性.md)。

## 三位一体协作

`cross-agent-dev-workflow-skill` 将阶段状态保存在相关层 `5_代办.md`；`cross-agent-scratchpad-skill` 按需把稳定的治理偏好、审计范围和续办事项写入对应层。二者均使用上述按范围读取与有意义更新规则。详见 [交付流程联动](联动/cross-agent-dev-workflow.md) 和 [临时脚本联动](联动/cross-agent-scratchpad.md)。
