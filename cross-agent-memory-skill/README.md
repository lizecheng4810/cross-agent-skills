# cross-agent-memory

跨 Agent / Harness 的工作区就地记忆技能。它把项目知识放在项目里，并通过**精简索引与按需展开**支持快速交接。

## 设计要点

- 技能对真实工作区任务常开，但常规接手只读根层 `0_索引.md`、当前 `5_代办.md`，以及目标范围层的索引、交接和相关主题文件。
- 工作区按独立、可复用的上下文边界规划 1~N 层；记忆层不是目录树镜像。只有首次初始化、结构变化或明确需要时才做完整审计。
- 新层默认只有 `0_索引.md` 和 `5_代办.md`；主题文件有内容时再创建。旧式六主题文件布局持续兼容。
- 任务结束只写入持久且有复用价值的变化；写前重读目标文件、合并、检查指纹、回读确认。
- 用户明确标记为跨项目通用的知识才写入根目录 `记忆_通用/`，各层链接到它，不复制全文。

## 快速使用

工具可选，支持快速定位与显式完整审计：

以下命令从 `cross-agent-memory-skill` 技能目录运行；从套件根目录运行时，在 `工具\` 前加 `cross-agent-memory-skill\`。

```powershell
# 仅检查工作区根层（默认快速模式）
python 工具\记忆管家.py 接手 "<工作区>"

# 仅检查目标路径上的记忆层
python 工具\记忆管家.py 接手 "<工作区>" --scope "<工作区内的目标目录或文件>"

# 显式执行整个工作区审计
python 工具\记忆管家.py 接手 "<工作区>" --full-audit
python 工具\记忆管家.py 检查 "<工作区>"

# 默认最小模板；--完整模板保留兼容旧布局的所有主题文件
python 工具\记忆管家.py 建层 "<目标目录>" --层 1
python 工具\记忆管家.py 建层 "<目标目录>" --层 1 --完整模板

# 按范围做词面检索，再打开少量来源
python 工具\记忆管家.py 检索 "<工作区>" "模块名" --term "关键符号" --scope "<子目录>" --top 10
```

搜索是大小写不敏感的词面匹配，不是语义检索。工具输出的目录候选只供人工判断，不会自动建层。

## 设计依据与边界

- [Agent Skills 规范](https://agentskills.io/specification)建议用短的核心 `SKILL.md` 配合按需参考文件；本技能将任务路由与细则分开。
- 一篇 [filesystem memory 预印本](https://arxiv.org/abs/2607.26637)在其研究设置中发现，组织良好的文件记忆可降低较大记忆库的检索成本，但层级组织本身不保证更好的答案，长期维护质量仍是关键。本设计因此同时减少默认读取和无意义写入。
- [LongMemEval-V2](https://arxiv.org/abs/2605.12493)提供了值得借鉴的记忆能力维度：稳定状态、动态变化、工作流程、环境陷阱和前提意识。该研究面向 Web agent 场景，本项目只借用这些维度作为未来评估清单，不宣称已达到论文基准。
- 曾评估 [OKF Agent Memory](https://github.com/okf-memory/okf-agent-memory) 的索引/BM25 路线；当前不引入完整运行时和新记忆格式，避免迁移、安装与维护成本。当前词面检索透明且无额外依赖，但无法自动找同义表达。

发布后可在有真实大型项目的情况下做前后对照：恢复关键交接信息的正确率、读取文件/字符数、完成接手所需操作数、陈旧或冲突记忆的发现率。结构精简本身不是质量证明。

## 包内文件

- `SKILL.md`：常驻核心协议和按需参考文档路由。
- `references/`：接手检索、分层审计、并发安全和通用知识细则。
- `_模板/`：索引、交接恢复点及需要时创建的主题文件。
- `联动/`：与交付流程和临时脚本治理的协作约定。
- `工具/`：可选的跨平台 Python 工具及 Windows 薄封装。
- `安装指引.md`：支持的 Harness 安装位置和首次接手方式。

详细协议见 [SKILL.md](SKILL.md)。
