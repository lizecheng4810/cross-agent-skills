# 与 cross-agent-dev-workflow-skill 的联动约定

本技能与 `cross-agent-dev-workflow-skill`（项目交付总流程）是**三位一体**关系：**dev-workflow 掌舵、memory 记账、本技能打扫**。dev-workflow 的三个阶段都会产生临时脚本和遗留物——**怎么建、怎么复用、怎么删，全部委托本技能的协议**。

## 一、dev-workflow 各阶段对本技能的委托点

| 阶段（dev-workflow） | 委托本技能的动作 | 对应本技能协议 |
|---|---|---|
| 阶段 0 接手 | 本机配置检查（库路径可达性）+ 遗留物审计（增量） | 节点 0 / 节点 1 |
| 阶段 1 研发 | 研究/原型/数据处理脚本：先查库复用 → 没有才建 → 建在外部库 + 登记 | 节点 2 |
| 阶段 2 测纠 | 测试/复现/比对脚本同上；测试输出与证据留存（外部库 `reports/` 或项目文档，不污染工作区） | 节点 2 |
| 阶段 3 整理发布 | **遗留物分级处置**：A 自己 / B 复用迁入 `reusable/` / C 无价值记录后清理 / D 来源不明→隔离+等用户确认 | 节点 1 分类表 |
| 收尾 | 本次脚本收编/清理/隔离 + 索引更新 + 审计留痕 | 节点 3 |

## 二、删除红线（dev-workflow 明确承诺遵守）

- 其「整理发布」涉及删除/移动/重命名一律走本技能分级协议，**绝不越级**：真实工程文件、构建配置、依赖清单、文档、数据文件、git 跟踪文件、拿不准的文件默认绝不自动删；来源不明只隔离 + 报告 + 等用户确认；优先回收站而非永久删除。
- 用户授权「全部权限」不解除红线——效率授权不是破坏授权。

## 三、本技能的结论写回（经 memory 中转，读后改不覆盖）

| 信息 | 去处 |
|---|---|
| 「该工作区已审计 + 日期 + 结论」 | 记忆 `1_项目架构.md` / `5_代办.md`（下轮增量审计） |
| quarantine 待拍板项 | 记忆 `6_需要我配合.txt`（dev-workflow 发布报告中显式列出） |
| 迁移/清理依据与结果 | `决策.md` + 外部库 `reports/`（dev-workflow 发布清单「无未处置遗留物」的证据） |
| 用户脚本治理偏好 | 记忆 `3_个性化需求.md` |

## 四、dev-workflow 未安装本技能时的降级

其 SKILL.md §六 三条铁律已兜底：临时脚本绝不落工作区、删除先问用户；装回本技能后补做一次遗留物审计。
