# 与 cross-agent-memory 的联动约定

本技能与 `cross-agent-memory` 是共生关系：memory 负责「理解和记录项目知识」，本技能负责「临时脚本治理」。**两者共用同一个接手任务入口，一次深度阅读同时服务两者。**

## 一、接手任务入口（合并流程）

```
接手任务
 ├─ 1. 读本机配置 ~/.agent-tsg/config.json（本技能）→ 未配置则问用户要临时脚本库路径
 ├─ 2. 读项目记忆 记忆第X层/（memory 协议：有记忆读记忆，无记忆深读项目）
 ├─ 3. 记忆中有「已审计」标记？ ──有──→ 跳过全量审计，只看增量
 │        └─没有→ 执行遗留物审计（本技能节点1），结果写回记忆
 ├─ 4. 执行任务（创建脚本走本技能节点2；踩坑/偏好随时写记忆）
 └─ 5. 收尾：处置本次脚本（节点3）+ 更新索引 + 按「读后改不覆盖」更新记忆
```

## 二、信息写到哪里（一个事实一个出处）

| 信息 | 写入位置 | 说明 |
|---|---|---|
| 本机临时脚本库路径 | 本机 `~/.agent-tsg/config.json` | **不放记忆**——机器专属绝对路径跨设备不通用 |
| 用户对治理的偏好（保留期、命名、敢不敢删） | 记忆 `3_个性化需求.md` | 用户亲口说的偏好是最高价值 |
| 「该工作区已完成遗留物审计 + 日期 + 结论」 | 记忆 `1_项目架构.md` 末尾或 `5_代办.md` | 避免下一个 Agent 重复全量扫描 |
| 脚本相关的坑（路径失效、依赖、必须在工作区跑等） | 记忆 `2_踩坑日志.md` | 问题/原因/解决/影响 |
| 待迁移/待清理/待审计 | 记忆 `5_代办.md` | 跨 Agent 接续任务 |
| quarantine 待用户拍板项 | 记忆 `6_需要我配合.txt` | 按重要性排序 |
| 每次保留/迁移/删除的依据和结果 | 记忆 `决策.md`（可选扩展）+ 库 `reports/` | 审计留痕，可回溯 |
| 可复用脚本的知识（哪个脚本好用、怎么用） | 库 `manifests/index.json`（结构化）+ 记忆 `4_提示词配方.md`（经验性） | 索引管事实，记忆管经验 |

## 三、并发安全

- 更新记忆一律遵守 memory 的「更新前先深读现有 6 件，读后改不覆盖」。
- 更新 `manifests/index.json` 前先重新读盘（可能被其他 Agent 刚写过），追加/修改自己的条目，**不整文件重写别人的条目**；工具已兜底——保存前重读磁盘做指纹比对（借鉴 memory 的 `记忆索引.json` 思想）+ 原子写入，检测到并发改动会拒写并提示重读合并。
- sessions 子目录按 `<项目名>/<日期-任务slug>/` 隔离，天然减少并发冲突。
- **一键接手入口**：`python 记忆管家.py 接手 <工作区>` 一条命令完成「扫描记忆层 + 层级完整性检查 + 各层并发校验 + 本库配置联动检查」，本技能节点 0 的步骤 2 读完记忆后可直接跑它（配置联动检查含在内）。
- **署名统一**：`配置 --name <署名>` 写入本机配置 `agent_name`，记忆管家与临时脚本管家共用；`登记/迁移/索引` 的 `--by` 省略时自动取它。

## 四、层级对应

- 库路径配置是**设备级**事实（每台机器一份）→ 不属于任何记忆层。
- 治理偏好属于**根记忆层（记忆第一层）**（工作区通用）。
- 某项目的遗留物审计结论、quarantine 项属于**该项目对应的记忆层**（按根层 `0_索引` 的「分层方案」，层号=记忆层级序数；层数由 Agent 深度研究项目后自主决定，不固定三层）。
