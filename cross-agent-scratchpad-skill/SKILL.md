# 跨 Agent / 跨 Harness 临时脚本治理技能

## 这个技能是什么

一套让任何 Agent / Harness 在任何工作区里**统一管理临时脚本全生命周期**的协议：
**临时脚本不进项目工作区，统一存放在用户指定的外部脚本库；创建前先复用；遗留物定期审计迁移；一切决策沉淀进 cross-agent-memory。**

与 `cross-agent-memory` 的分工：

| 技能 | 职责 |
|---|---|
| `cross-agent-memory` | 理解项目、沉淀知识（读什么、为什么、踩过什么坑） |
| 本技能 | 治理临时脚本（建在哪、能不能复用、何时删、迁到哪） |

三位一体（memory · scratchpad · dev-workflow）共用同一个「接手任务入口」，联动细节见 `联动/cross-agent-memory.md` 与 `联动/cross-agent-dev-workflow.md`。

## 一、强制生命周期协议（每次任务都要走）

### 节点 0：接手任务时（强制第一步，与 cross-agent-memory 合并执行）

1. **读本机配置**：读取 `~/.agent-tsg/config.json`（Windows 为 `C:\Users\<用户>\.agent-tsg\config.json`）。
   - **已配置** → 验证路径仍存在可写；不可达（外接盘缺失/网络盘断开）→ **停下来请求用户重新指定，绝不静默回退到工作区**。
   - **未配置** → **必须先询问用户**：「本设备的临时脚本统一存放位置在哪里？」拿到路径后写入本机配置（用工具 `配置` 命令，或手工写入），**绝不擅自替用户选路径**。
2. **读项目记忆**：按 cross-agent-memory 协议读 `记忆第X层`。记忆中若标记「本工作区已完成遗留物审计（日期）」→ 跳过全量审计，只看增量；否则先完成节点 1。
   > 工具捷径：`python 记忆管家.py 接手 <工作区>` 一条命令完成「记忆_通用 检查 + 扫描记忆层 + 层级完整性检查 + 各层并发校验 + 本机配置联动检查」，三技能（含 cross-agent-dev-workflow 的阶段0）共用的接手第一步。

### 节点 1：首次接手工作区——遗留物审计

深度阅读项目（有记忆先读记忆）后，把可疑文件分四类，**严格按下表处置，不得越级**：

| 分类 | 判定特征 | 默认动作 |
|---|---|---|
| A. 本次自己建的临时脚本 | 本会话内创建 | 建在外部库（见节点 2），任务结束按节点 3 处置 |
| B. 历史 Agent 遗留、明显是临时脚本、有复用价值 | 命名含 tmp/test/demo/scratch/debug、无 git 跟踪、单文件无依赖、用途可辨识 | **迁移**到外部库 `reusable/`（先登记元数据），生成索引 |
| C. 历史 Agent 遗留、一次性无价值 | 同上特征但用途已失效/与项目无关/重复 | **删除前写入审计记录**（记入记忆 `决策.md` 与审计报告）；删除方式优先系统回收站（可手工拖回收站），工具 `清理` 为**永久删除**（索引保留内容哈希留痕），拿不准就先 quarantine |
| D. 来源不明 / 疑似无关 / 可能是用户有意保留 | 运维脚本、数据修复脚本、迁移脚本、未引用但命名正式、判断没把握 | **只隔离+报告**：生成审计报告，移到外部库 `quarantine/`（保留原相对路径记录，可随时移回），列入记忆 `6_需要我配合.txt`，**等用户确认后才能删** |

> **红线（绝不可违反）**：源代码、构建/CI 配置、依赖清单（package.json/requirements.txt 等）、文档、数据文件、被 git 跟踪的文件、任何拿不准的文件——**默认绝不自动删除**。宁可多隔离，不可误删。

审计工具：`python 工具/临时脚本管家.py 审计 <工作区路径>`（启发式扫描，输出候选清单），Agent 再逐个深度判断分类。结果写入 `reports/审计-<工作区名>-<日期>.md` 和记忆。

### 节点 2：创建临时脚本时（强制）

1. **先复用**：检索外部库索引（`python 工具/临时脚本管家.py 查 <关键词>` 或直接读 `manifests/index.json`），按用途/语言/适用范围匹配。有合适的 → 直接用或小改复用，并在索引中更新「使用次数/最后使用时间」。
2. **没有才新建**，且**必须建在外部库**：
   - 大概率可复用的工具类脚本 → `<根>/reusable/`
   - 本次任务专用的一次性脚本 → `<根>/sessions/<项目名>/<日期-任务slug>/`
   - **绝不在项目工作区里新建临时脚本**。若框架/工具强制要求脚本在工作区内运行（如相对路径依赖），先建到外部库，用完立即迁走或删除，并在记忆 `2_踩坑日志.md` 记录此约束。
3. **登记**：新建即登记元数据（`python 工具/临时脚本管家.py 登记 <文件> --purpose "用途" --reuse one-off|reusable --project <项目名>`）。

### 节点 3：任务结束 / 对话结束时（强制，与 cross-agent-memory 更新合并）

对本次创建/使用过的脚本逐个判断：

- **有复用价值** → 提炼进 `reusable/`（补全元数据：用途、参数、依赖、适用范围）；
- **无复用价值** → 删除（优先回收站；工具 `清理 --yes` 为永久删除，索引状态改 `deleted` 并留哈希）；
- **判断不准** → 移入 `quarantine/`，列入记忆 `6_需要我配合.txt` 请用户拍板。

同时：更新索引、写审计/清理记录到 `reports/`、按联动文档更新 cross-agent-memory 对应记忆文件（**读后改不覆盖**）。

## 二、外部临时脚本库结构

```
<用户指定的根目录>/
├── reusable/          # 已验证可复用脚本（全局共享，跨项目）
├── sessions/          # 一次性任务脚本，按 <项目名>/<日期-任务>/ 隔离
├── quarantine/        # 来源不明候选，等用户确认，保留可回迁信息
├── manifests/
│   └── index.json     # 唯一索引：每个脚本的元数据（含内容哈希）
└── reports/           # 审计报告、清理决策清单
```

元数据字段（存于 `manifests/index.json`，每个条目）：

```json
{
  "id": "20260904-a1b2",
  "file": "reusable/检查文件编码.py",
  "purpose": "批量检测文本文件编码",
  "language": "python",
  "reusability": "reusable | one-off | unknown",
  "status": "active | archived | quarantined | deleted",
  "project": "新闻爬虫 或 global",
  "created_by": "agent名/harness名",
  "created_at": "2026-09-04T10:00:00",
  "source_workspace": "逻辑工作区标识（不存机器专属绝对路径）",
  "origin_path": "工作区内原始相对路径（quarantine 回迁用）",
  "use_count": 2,
  "last_used": "2026-09-04",
  "content_hash": "sha256:..."
}
```

> 跨设备注意：索引和记忆里只记**逻辑工作区标识**；机器专属的绝对路径只存在本机 `~/.agent-tsg/config.json`。

## 三、工具脚本

`工具/临时脚本管家.py`（主工具，跨平台，需 Python 3.8+）：

| 命令 | 作用 |
|---|---|
| `配置 [--path <目录>] [--name <署名>]` | 查看/设置本机临时脚本根目录（写入 `~/.agent-tsg/config.json`）并初始化目录结构；`--name` 设置默认署名 `agent_name`（记忆管家/临时脚本管家共用，登记/迁移留痕一致） |
| `查 <关键词> [--lang py] [--project X]` | 检索索引找可复用脚本 |
| `登记 <文件> --purpose ... [--reuse one-off] [--move] [--project X]` | 把脚本收编入库并登记元数据（`--move` 移动入库，默认复制；`--by` 省略时自动取本机配置 `agent_name`） |
| `审计 <工作区>` | 启发式扫描工作区内的疑似临时脚本，输出候选清单 |
| `迁移 <文件> --to reusable\|sessions\|quarantine [--project X]` | 移动脚本入库并更新索引（quarantine 记录原路径，可回迁） |
| `使用 <文件或id> [--note N]` | 标记脚本被复用过（使用次数+1，更新最后使用时间） |
| `回迁 <文件或id>` | 把 quarantine 中经用户确认误伤的脚本移回工作区原路径 |
| `清理 [--project X] [--before 日期] [--quarantined] [--yes]` | 按索引处置 one-off/过期脚本；`--quarantined` 处置**用户已确认**的隔离项（默认只列清单，`--yes` 才执行） |
| `报告` | 输出库内现状摘要（各区数量、最近使用、待确认项） |

**并发安全（借鉴 cross-agent-memory 的指纹校验思想）**：索引每次保存都走**原子写入**（临时文件+替换，不会留半截 JSON）；保存前重读磁盘做**指纹比对**，若索引已被其他 Agent 改过则拒绝写入并提示重新读取合并——工具层兜底 + 「先读再改」协议纪律双保险。

`工具/临时脚本管家.ps1`：Windows 薄封装（转发到 Python；无 Python 时提供 `配置/查/审计` 的 PowerShell 原生降级实现）。

**工具不是必须的**——没有 Python 时，Agent 按本协议手工读写目录和 `index.json` 也完全成立。

## 四、与 cross-agent-memory 的联动约定（必读 `联动/cross-agent-memory.md`）

与 `cross-agent-memory`、`cross-agent-dev-workflow-skill`（项目交付总流程）**三位一体**：dev-workflow 掌舵（研发→测纠→整理发布三阶段 + 证据制验收门 + 停止闸），其研发/测纠阶段的临时脚本治理、发布阶段的遗留物处置**全部委托本技能的分级协议**（含删除红线）。联动细节见 `联动/cross-agent-dev-workflow.md`。

速记版：

- 本机库路径 → 本机 `~/.agent-tsg/config.json`（不放记忆，跨设备不通用）；**用户对临时脚本治理的偏好**（保留期、命名、删不删）→ 记忆 `3_个性化需求.md`。
- 审计结论「该工作区已审计 + 日期 + 遗留了什么」→ 记忆 `1_项目架构.md` 或 `5_代办.md`。
- 脚本相关的坑（路径失效、依赖冲突、必须在工作区跑的约束）→ `2_踩坑日志.md`。
- 待迁移/待确认/待清理 → `5_代办.md`；需要用户拍板的 quarantine 项 → `6_需要我配合.txt`。
- 每次保留/迁移/删除的依据和结果 → `决策.md`（可选扩展）。
- 更新记忆一律遵守 cross-agent-memory 的「先深读现有 6 件，读后改不覆盖」。

## 五、强制使用的边界（诚实声明）

本 skill 通过协议强约束**加载了它的 Agent/Harness**。它无法从技术上强制未安装本 skill 的第三方工具。为最大化覆盖：
- 已安装本 skill 的 Agent：每次任务必须走节点 0→3 全流程；
- 发现工作区内新出现的、非本协议创建的临时脚本 → 下一轮审计时收编。

## 关键原则

1. **外部存放**：临时脚本一律不进项目工作区。
2. **先复用后创建**：建脚本前必查索引。
3. **分级处置**：自己的脚本自动治理；历史遗留先判复用价值；来源不明只隔离+确认；**真实工程文件绝不自动删**。
4. **路径用户定**：未配置必问用户，失效必重问，绝不静默回退。
5. **一切入记忆**：判断、偏好、决策写入 cross-agent-memory，跨 Agent/Harness 延续，不重复扫描、不重复提问、不重复造脚本。
